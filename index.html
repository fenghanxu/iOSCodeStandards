iOS 共同开发代码规范

本文用于 BusMate 两名或多名 iOS 开发人员共同开发时统一代码风格、文件结构和常用写法。新代码优先遵守本文；历史代码按原有结构维护，修改时逐步统一。

1. 通用代码风格

1.1 文件结构

普通 Swift 类型统一按以下顺序组织：

import UIKit

class ExampleView: UIView {
    // MARK: - Public

    // MARK: - UI

    // MARK: - Init

    // MARK: - Private

    // MARK: - ButtonClick
}

extension ExampleView: ExampleViewDelegate {
}
  • Public：外部可访问属性、identifier、Delegate、公开数据入口。
  • UI：所有页面控件和懒加载属性。
  • Init：系统初始化方法、viewDidLoad、cell(with:)、setData 等入口。
  • Private：buildUI()、私有模型、数据处理和内部辅助方法。
  • ButtonClick：按钮点击方法；没有按钮时不保留空分区。
  • DataSource、Delegate 和其他协议实现统一写在类外 extension 中。

1.2 排版

  • 控件属性统一使用 lazy private var，控件的固定样式在闭包中完成。
  • 代码保持紧凑，闭包内部不插入无意义的空行。
  • 方法调用参数在合理长度内保持一行，不为了单个参数机械换行。
  • buildUI() 先设置背景和基础属性，再添加控件；空一行后写约束；每组约束之间空一行。
  • 一个方法只完成一个主要动作，布局、数据绑定、网络请求需要拆开。
  • 新代码避免强制解包；必须使用时先确认前置条件。

1.3 UI 约束

  • 页面约束统一使用 SnapKit，不在同一个视图中混用 SnapKit 和手写约束。
  • 添加控件和设置约束分开书写，控件只在一个位置添加和约束。
  • 页面背景优先使用 Color.background，卡片背景使用 .white。
  • 安全区、导航栏高度和底部高度统一使用项目已有的 safeAreaTop、safeAreaBottom、totalTopHeight(_:) 等方法。

1.4 公共样式

  • 颜色优先使用 Color.theme、Color.textTheme、Color.textSub、Color.textWeak、Color.line 等语义化颜色。
  • 字号优先使用 16、14、12；特殊标题可按页面视觉需要使用 18 或 20。
  • 不在页面中重复定义同一颜色、字体、间距和安全区计算。
  • 多个控件样式相同但业务含义不同，仍分别声明各自的懒加载属性；不要为了少写几行创建页面级工厂方法。

2. ViewController 规范

2.1 基本职责

ViewController 负责页面生命周期、页面组装、数据源/代理、页面跳转和页面级网络调用；不直接修改 Cell 的私有控件。

2.2 生命周期

普通页面统一先构建 UI，再请求数据：

override func viewDidLoad() {
    super.viewDidLoad()
    buildUI()
    buildData()
}

buildUI() 的常用顺序：隐藏系统导航栏、设置背景色、添加导航栏、添加主要内容视图、设置约束。

2.3 控件和网络

  • 页面控件全部使用 lazy private var。
  • 网络请求统一使用项目的 networkManage，不在页面中单独创建 MoyaProvider。
  • 网络闭包使用 [weak self]，进入闭包后安全解包。
  • 成功时先保存模型，再刷新 UI；失败时统一使用 HUD.show(string: reason.errorString)。
  • 必要参数缺失时先提示并 return。

2.4 ButtonClick

按钮名称为 taskButton 时，点击方法固定为 taskButtonClick：

lazy private var taskButton: UIButton = {
    let button = UIButton()
    button.addTarget(self, action: #selector(taskButtonClick), for: .touchUpInside)
    return button
}()

@objc
private func taskButtonClick() {
}

按钮点击方法必须放在 // MARK: - ButtonClick 下。

3. UIView / 普通自定义 View 规范

  • 类名使用业务名称加 View，例如 MessageBoardView、DateSelectionView。
  • 根 View 负责容器布局和对外回调，内部控件保持私有。
  • 控件使用懒加载，约束统一使用 SnapKit。
  • 需要传入数据时，使用初始化方法或 setData/setModel，不要让外部逐个修改内部控件。
  • 只在公共组件确实具有稳定复用价值时抽取公共方法；页面中相似控件按业务名称分别声明。
  • 复杂 View 的网络请求、页面跳转和 HUD 提示由外部控制器或 ViewModel 处理。

4. UITableViewCell 规范

4.1 基础结构

自定义 Cell 必须有统一复用标识：

static var identifier: String { String(describing: self) }

注册和获取 Cell 时使用同一个 identifier，不使用散落的字符串常量。

Cell 初始化时调用 buildUI()，默认关闭选中效果：

override init(style: UITableViewCell.CellStyle, reuseIdentifier: String?) {
    super.init(style: style, reuseIdentifier: reuseIdentifier)
    buildUI()
}

required init?(coder: NSCoder) {
    fatalError("init(coder:) has not been implemented")
}

4.2 数据赋值

Cell 对外提供统一的数据入口，内部保存模型并完成控件赋值：

private var model: ExampleModel?

func setData(_ model: ExampleModel?) {
    self.model = model
    titleLabel.text = model?.title
}
  • ViewController 只调用 setData/setModel，不直接修改 Cell 内部控件。
  • Cell 只负责展示和格式化，不发起网络请求、不执行页面跳转。
  • 必须实现 prepareForReuse()，清空文本、图片、隐藏状态、选中状态和异步结果。

4.3 Cell 布局

  • buildUI() 中先设置 selectionStyle、背景色，再添加控件和约束。
  • Cell 内部控件使用 lazy private var。
  • 图片、标题、辅助信息、按钮按照 Cell 自身职责组织，不能把整页 UI 堆进一个 Cell。
  • 动态展示状态由 setData 统一更新，避免复用后残留上一条数据。

5. Delegate 规范

5.1 使用场景

Cell、View 或弹窗需要向外传递点击、输入、选择结果或其他数据时使用 Delegate；网络请求和页面跳转仍由上层处理。

5.2 命名和声明

协议名为“组件名 + Delegate”，例如 DriverNearBusCellDelegate：

protocol DriverNearBusCellDelegate: AnyObject {
    func driverNearBusCell(cell: DriverNearBusCell, returnButton button: UIControl, returnModel model: TaskListDataModel?)
}

weak var delegate: DriverNearBusCellDelegate?
  • Delegate 协议继承 AnyObject 或 NSObjectProtocol。
  • Delegate 属性必须使用 weak。
  • Delegate 属性放在 identifier 下方，公开数据入口附近。
  • 方法名包含组件名称、触发控件或事件名称、返回数据名称。
  • 回调时传递当前组件 self 和必要的业务数据，不传递不相关页面状态。

6. UIButton 规范

  • UIButton 统一使用懒加载创建。
  • 事件绑定写在按钮的懒加载闭包中。
  • 点击方法使用“按钮名称 + Click”，并放在 ButtonClick 分区。
  • 不通过 tag 代替清晰的按钮点击方法；确需区分同类按钮时，tag 使用对应业务枚举值。
  • 按钮的文字、颜色、圆角、边框和状态统一在按钮创建或 setData 中配置。
lazy private var confirmButton: UIButton = {
    let button = UIButton(type: .custom)
    button.setTitle(language("确定"), for: .normal)
    button.setTitleColor(.white, for: .normal)
    button.backgroundColor = Color.theme
    button.layer.cornerRadius = 22
    button.addTarget(self, action: #selector(confirmButtonClick), for: .touchUpInside)
    return button
}()

7. UIImageView 规范

  • UIImageView 统一使用懒加载创建，约束使用 SnapKit。
  • 设置图片时使用 UIImage(named:)，不使用系统图标代替项目资源。
  • 开发阶段根据 UI 图确认图片位置，可设置临时背景色或占位图；最终联调前替换为正式资源并移除临时占位样式。
  • 根据用途设置 contentMode，图标通常使用 .scaleAspectFit，背景图根据设计使用 .scaleAspectFill。
  • 图片资源统一放入 Assets.xcassets，使用功能前缀命名。
lazy private var generalImageView: UIImageView = {
    let imageView = UIImageView()
    imageView.image = UIImage(named: "Frame")
    imageView.contentMode = .scaleAspectFit
    return imageView
}()

8. UITableView 页面规范

8.1 固定 Cell 列表

适用于公告、消息、设置等列表页：

  • TableView 使用统一背景色，隐藏滚动条，关闭系统分割线。
  • 注册 Cell 时使用 Cell.identifier。
  • 固定高度使用 rowHeight；动态高度依靠完整约束。
  • Header/Footer 和 estimated 高度按页面需要设置，减少刷新跳动。
  • numberOfRowsInSection 对可选数组使用 ?? 0。
  • cellForRowAt 先安全取得模型，再调用 Cell 的 setData。

8.2 多种 Cell / 多 Section 页面

  • 每一种 Cell 对应明确的 section 类型。
  • Section 类型、行数、行高、Header/Footer 高度由 ViewModel 或 section 描述统一维护。
  • cellForRowAt 根据 section 类型选择 Cell，不使用散落的魔法数字。
  • 未知 section 返回空 Cell，避免页面崩溃。
  • Cell 的数据展示和样式由 Cell 自身负责，ViewController 只负责组装。

8.3 刷新和分页

  • 下拉刷新时页码重置为 1，并暂时隐藏 Footer。
  • 第 1 页替换列表，后续页使用 append(contentsOf:) 追加。
  • 请求成功和失败都结束 Header/Footer 刷新状态。
  • 没有数据时隐藏 Footer；有数据时显示 Footer。
  • 达到总页数调用 endRefreshingWithNoMoreData()，否则调用 endRefreshing()。
  • 请求完成后同步调用 reloadData() 和 reloadEmptyDataSet()。

9. UIScrollView 页面规范

  • 页面使用 navigationView、scrollView、container 三层结构。
  • navigationView 不放进滚动内容；业务控件全部添加到 container。
  • scrollView.contentInsetAdjustmentBehavior = .never。
  • 关闭不需要的横向、纵向滚动条。
  • contentHeight 根据最后一个 UI 控件底部位置计算，最后保留约 20pt，不使用过大的估算值。
  • 第一张卡片通常从 totalTopHeight(self) + 12 开始，卡片左右间距通常为 12，卡片内部间距通常为 16。

10. UIView 弹窗规范

  • 业务弹窗统一使用自定义 UIView，不使用页面 present。
  • 弹窗文件放在 Company/Modal 对应功能目录中。
  • 居中确认弹窗和底部抽屉弹窗分别保持统一的容器结构和动画方式。
  • 根视图负责遮罩，bgView 负责内容，点击空白区域使用透明按钮处理。
  • 所有约束使用 SnapKit；显示和关闭分别封装为 show/showView 和 dismiss/dismissView。
  • 关闭动画完成后必须 removeFromSuperview()。
  • 弹窗通过闭包返回结果，网络请求和页面跳转由外部页面处理。
  • 有键盘监听时，在 deinit 中移除通知，并在关闭时 endEditing(true)。

11. Model 规范

  • 接口返回模型统一实现 Codable。
  • 属性默认使用可选类型，兼容后台字段缺失。
  • 每个模型显式声明 CodingKeys，完整映射后台字段。
  • 后台下划线字段转换为 lowerCamelCase，原字段保留在 CodingKeys。
  • 嵌套对象和数组创建明确的模型类型，不使用 Any? 代替真实结构。
  • 顶层 data 的 id 使用 idData，列表元素 id 使用 idList，其他 id 根据所属字典命名。
  • Model 只保存数据结构，不写 UI、网络请求和页面业务逻辑。

12. 网络接口规范

新增接口必须同时补充：API case、path、method、task、headers、Codable Model 和页面调用。

  • GET/POST 按真实接口文档配置，不根据接口名称猜测。
  • JSON body 使用 JSONEncoding.default，URL 参数使用 URLEncoding.default。
  • 需要 Token 的接口统一使用项目 Header 配置。
  • 网络请求统一使用 networkManage(target:type:completion:)。
  • 请求前校验必要参数；成功后先保存模型，再刷新 UI；失败后统一 HUD 提示。
  • 调试时以真实返回 JSON 修正 Model 和 CodingKeys，不在页面临时解析字典。

13. 项目目录和文件命名

ProjectName/
├── AppDelegate.swift                 # 应用生命周期
├── SceneDelegate.swift               # Scene 生命周期
├── ViewController.swift              # 工程模板遗留入口（如不使用，不再新增业务）
├── Bridging-Header.h                 # Swift 与 Objective-C 桥接声明
├── Info.plist                        # 应用配置
├── BusMate.entitlements              # 权限与能力配置
├── Assets.xcassets/                  # 图片、颜色、图标等资源
├── Base/                             # 全局基础能力与通用 UI
│   ├── Control/                      # 可复用控件、视图、控制器
│   ├── Extension/                    # Foundation/UIKit 等扩展
│   └── ThirdPod/                     # 对第三方库的二次封装
├── Company/                          # 公司/业务平台级复用组件
│   ├── Modal（模态窗）/              # 业务通用弹窗
│   ├── Services(服务)/               # 跨模块业务服务
│   └── Template(模版)/               # 业务通用 UI 模板
├── Module/                           # 按业务功能拆分的模块
├── Network/                          # 网络请求、接口定义和网络模型
│   ├── Assist/                       # 请求辅助模型与配置
│   ├── Core/                         # 网络核心封装
│   └── Model/                        # 接口响应/请求模型
├── Base.lproj/                       # Storyboard 等本地化界面资源
└── 代码规范/                          # 开发规范与示例文档
  • 控制器放在模块的 VC，页面视图和 Cell 放在 View，ViewModel 放在 ViewModel。
  • 目录和文件使用稳定的英文业务名，历史中文目录不强制重命名。
  • 控制器使用 VC 后缀，Cell 使用 Cell，视图使用 View，模型使用 Model。
  • 文件名与主要类型保持一致。
  • 公共代码放 Base，跨模块业务能力放 Company，单模块代码不要放入全局目录。

维护原则：新代码优先遵守本文；历史代码按原有结构维护，修改时逐步统一。
